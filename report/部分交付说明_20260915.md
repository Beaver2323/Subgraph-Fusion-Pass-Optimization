## 交付对象与验收范围

本仓交付的是冻结 PyTorch 社区优化合同在 NPU `triton_experimental` 上的兼容性证据、最小适配/修复及性能处置，不是全部 Inductor pass 的完备支持声明，也不是已发布的 torch_npu wheel。

当前正式统计为 **54/69 个独立单元（78.26%）**；71 个跟踪 ID 中有两个去重别名。T-076～T-086原范围33项与T-087～T-113新增21项分开保留证据。188个静态候选划分为71个选中ID、87个延期和30个非计数项，不等于全体FX pass，也不是当前正式验收分母。

T-102五项已完成安装态原合同、修复、边界及独立六臂性能，4项改善、1项回退。详见[T-102逐pattern讲解与证据](../results/current/T-102/README.md)。“完成”包含明确回退与受限处置，不意味着54项全部提速、全面对齐或新规则历史再认证通过。

## 接收方阅读顺序

1. [活动单元矩阵](current_acceptance_unit_matrix.md)：每个单元的 GPU、NPU、修复、对齐与性能状态；CSV 同目录可用于筛选。

3. `results/current/T-xxx/`：逐 pattern 的结果、对照、功能/性能讲解及机器可读门禁。
4. `issues/REF-.../`：真实问题、适配/根因/修复报告、必要调用栈；`evidence/` 保存前后 FX、IR 和生成代码。历史 FAIL 不删除。
5. [最新离线审计](../results/audits/latest.json)：校验引用、正文哈希与计数；审计本身不是新设备测试。

## 接收时必须同时接受的边界

- T-076/T-077 保留历史闭环结论，严格历史再认证仍有 **41 项 pending、3 项 exempt**，不能称新规则全量再认证通过。

- 性能是明确输入域内的同后端 OFF/ON 测量；局部微基准不能外推模型端到端、整个训练或其他 dtype/shape。
- 原社区没有比较的数值范围不能由退出码 0 补成精度 PASS；其他后端历史不能迁移为 experimental 结论。
- 各批次按自身已验签的源码指纹、输入和测量方法交付。T-102 本轮部署不等于其他历史批次已在这个新安装态重新认证；先前 T-106 等性能保留原执行快照和时间。
- 未闭环任务、GPU 补证以及性能回退继续列入矩阵，不从交付统计中悄悄删除。

# T-069 triton_experimental MSPTI/Event benchmark 验证报告

## 1. 结论

T-069 / TE-AUTO-002 已完成。默认 MSPTI 自动加载、启动前显式预加载、配置关闭后的 Event
fallback，以及 MSPTI 运行态记录失败后的 Event fallback 均通过安装态真实 NPU 验证。

- P-025 安装态 heuristics 与当前源码 SHA256 均为
  `9dbcfa13b15526f85f9137460dd064b458a15e25d1c8850d79ffeb02445818fc`；
- 自动 dlopen 与进程启动前 `LD_PRELOAD` 均获得 `175/175` 条 Triton 记录，且都选中
  `XBLOCK=3424`，默认自动加载有效；
- 三轮交错 paired 中，MSPTI autotune benchmark wall 中位数为 `115.481260 ms`，Event 为
  `877.190360 ms`，MSPTI 改善 `86.84%`；
- MSPTI peak allocated 为 `20,989,952 B`，Event 为 `276,974,592 B`，少
  `255,984,640 B`（`92.42%`）；Event 路径的 256 MB L2-clear cache 是主要差额；
- 同一最终图的 MSPTI device-time P50 中位为 `30.40 us`，分组 Event 为 `148.07 us`，后者
  为前者 `4.89x`；因此不能把 Event 数值当成小 kernel 的真实 device duration；
- 强制 MSPTI 返回 `None` 后，系统执行 7 个 Event candidate bench，warning 原因正确，数值
  仍 allclose；fallback 安全性成立。

最终状态：`verified-mspti-device-time-preferred-event-fallback-retained`。无需新增产品修改，
不提交、不推送。

## 2. 配置生命周期与分支

`enable_mspti=True` 在 experimental 后端 `_activate()` 时执行一次 best-effort 加载：根据当前
`ASCEND_HOME_PATH`/`ASCEND_TOOLKIT_HOME` 找到 `tools/mspti/lib64/libmspti.so`，以
`RTLD_GLOBAL` 加载并保存 process-lifetime handle。`autotune_mspti` 则在每次 benchmark 时
实时读取，并同时要求 Python `KernelMonitor` 可导入且 `LD_PRELOAD` 含 `libmspti.so`。

实际顺序是：

1. 多候选 pre-run，淘汰不可运行或 UB overflow 的 tile；
2. MSPTI 可用时，在一个 monitor session 中按 launcher 顺序执行 `warmup + active`；
3. 只保留 `triton*` 记录，要求记录数严格等于 launcher 数乘迭代数；
4. 记录缺失或 monitor 异常时回退 grouped NPU Event；
5. Event batch 外层异常时再回退单 launcher `bench()`。

本轮 static contract 29/29、合成合同 3/3 通过。合成合同覆盖 warmup 丢弃、非 Triton 记录
过滤、median 与 ns→ms 单位转换、记录数不匹配返回 `None`、monitor finally-stop，以及
`autotune_mspti` late opt-out。

## 3. 真实 NPU 覆盖

环境为 Ascend910B2、CANN 9.0.1、Python 3.11.15、PyTorch
`2.14.0a0+git8e86e0a`、torch_npu `2.14.0a0+git83cc452`。所有 worker 从
`/home/z50063656/tmp` 启动，使用 P-025 独立 venv，fresh compile 且禁用 Inductor/Triton
cache。目标图为一条 FP32 pointwise `sin + 0.5*cos`，legacy 候选集确保进入真实 autotune；
每次最终均生成一个 experimental Triton kernel 并与 NPU eager allclose。

真实运行共 10 个 worker：

- smoke：自动加载、显式预加载、显式 Event、MSPTI 强制失败，共 4/4；
- paired performance：自动 MSPTI 3 轮、Event 3 轮，共 6/6；
- 两模式交错使用两张卡，第 2 轮交换设备；每轮稳态 warmup 20、runs 200；
- autotune MSPTI 固定 warmup 5、active 20，7 个 runnable launcher 因而为 175 条记录；
- 三轮 MSPTI 与 Event 都稳定选中 `XBLOCK=3424, num_warps=8, num_stages=1`。

大 tile 在预编译阶段出现 UB overflow 并被正常淘汰；至少 7 个合法候选进入 benchmark，最终
编译和数值均通过，因此这些日志属于候选有效性筛选，不是 case failure。

## 4. 性能与计时可信度

| 指标（三轮中位） | MSPTI auto | Event fallback | MSPTI 相对 Event |
|---|---:|---:|---:|
| autotune benchmark wall | `115.481260 ms` | `877.190360 ms` | `-86.84%` |
| compile + first run | `20,478.785220 ms` | `20,659.469010 ms` | 仅记录，不单独归因 |
| peak allocated | `20,989,952 B` | `276,974,592 B` | `-92.42%` |
| 同图 MSPTI device P50 | `30.40 us` | `30.38 us`（独立 monitor 观测） | 相同 kernel 尺度 |
| 同图 grouped Event P50 | `148.07 us` | `155.05 us` | 均明显高于 MSPTI |

自动加载 smoke 与预加载 smoke 的 benchmark wall 分别为 `110.543260/110.743850 ms`，均为
175 条精确记录且选中同一配置，支持默认自动加载等价于 shell 预加载。三轮自动 MSPTI 的
同图 Event/MSPTI P50 比率中位为 `4.8866x`，说明小 kernel 上 Event 窗口仍混入 launch/rate
影响；设备时间结论以 MSPTI callback 为准。

Event 保留是正确的降级策略，但它不应成为默认：除了计时失真，`_do_bench_npu()` 每个
launcher 创建约 256 MB int cache 用于 L2 clear，因此本轮 Event peak 固定多约 244.13 MiB。
MSPTI 一个 session 批量覆盖所有 launcher，避免该内存与 7 次 Event bench wall 开销。

## 5. 与原生 torch_npu 路径的边界

原生 `torch_npu._inductor.runtime` 与 experimental 都要求 Python MSPTI 包、LD_PRELOAD marker
和严格记录数；原生 helper 返回 active 平均 device-us，并在 aggressive autotune 下由调用者
尝试 profiler batch fallback。experimental 的 timings 字典使用 ms，因此返回 active median
device-ms，并明确避免 autotune 内嵌 profiler，改用 grouped Event fallback。

这两条路径服务不同 autotuner，不应互相复制实现或混用单位。T-069 只证明 experimental
当前路径可用、快且 fallback 安全，不把该数据冒充原生 pass 的完成证据。

T-067 历史高并发运行曾出现间歇 MSPTI 记录失败；本轮自动/预加载 smoke 及三轮 paired 均未
复现加载失败，而强制失败验证已证明其降级闭环。结论是保留 warning 和 Event fallback，后续
在更高 monitor 并发或多 kernel launcher 场景持续监控记录完整性。

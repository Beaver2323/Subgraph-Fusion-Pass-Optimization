# T-070 triton_experimental Max(1,size) loop-merge 验证报告

## 1. 结论

T-070 / TE-FX-002 已完成。默认 `fold_max1_in_loop_merge=True` 必须保留：它把动态卷积输出
pointwise 的循环结构从 3 个 codegen 轴折叠为 1 个轴，动态 shape 与零元素输出均正确；关闭
后虽然普通卷积图仍能运行，但隔离 shape-factory 图会生成标量值与三维 store mask 的秩冲突，
所有 Triton config 编译失败。

- 静态合同 `22/22`，开启/关闭合成合同 `29/29 + 5/5`；
- 接受 10 个真实 NPU worker、19 次 eager/compiled 比较；
- 真实动态卷积图：开启 `4→1` 轴，关闭 `4→3` 轴，两组动态 shape 都正确；
- shape-factory：开启后两组正 shape 与 `[2,8,0,0]` 空输出正确；关闭后稳定暴露
  `Cannot broadcast, rank mismatch: [1], [1, 47, 264]`；
- 三轮同卡 paired：device mean 中位改善 `0.04%`，P50 中位回退 `0.06%`，P99 中位改善
  `0.75%`，属于稳态中性；peak 两侧同为 `418,934,272 B`；
- compile + first run 中位 `20,856.062/20,291.183 ms`，开启侧快 `2.71%`，但冷编译波动较大，
  仅作为结构缩减的支持证据，不单独归因。

最终 verdict 为 `verified-required-default-retained-no-product-change`。本轮不新增 P-026，不修改
产品源码，不提交、不推送。

## 2. 实现与配置生命周期

`_npu_fold_max1()` 递归把二元 `Max(1,e)` 折为 `e`。安装函数不是普通 FX pass，而是替换
`SizeVarAllocator._simplify_loops_impl` 整个类方法：

1. 原始 `sizes/strides/index_formulas` 保留；
2. 只为 merge 判定创建 `fsizes/fstrides/fformulas` 折叠副本；
3. 对每个公式仍执行 stride 对齐和线性 substitution 检查；
4. merge 后的真实 size 使用未折叠 size 相乘；
5. 返回的 size、reindex 和 prune 都来自真实 size 状态。

因此 `Max` 不直接泄漏为错误的 emitted extent。空 raw extent 为 0 时，未 clamp 的合并 extent
仍为 0；实际 clamped extent 则保留 `Max` 并得到非空大小。合成枚举覆盖 raw extent
`0/1/2/4`、clamped extent、布尔公式、非连续 gap 和 index-dependent Max，未发现误合并。

该 gate 是安装时读取：必须在 experimental 后端首次 activation 之前设定。类级 sentinel 使
安装幂等，但 activation 之后把 config 改为 False 不会撤销 patch。这是配置生命周期事实，
inventory 不应再把它写成 live-read。

## 3. 真实 NPU 功能与负向合同

环境为 Ascend910B2、CANN 9.0.1、Python 3.11.15、PyTorch
`2.14.0a0+git8e86e0a`、torch_npu `2.14.0a0+git83cc452`。所有 worker 从
`/home/z50063656/tmp` 启动，使用 P-025 安装 venv、fresh cache 与 experimental backend。
安装态 `fx_passes.py` SHA256 为
`06c198242e8b6a42932ac1149a64bb6d75de2b91a39e51e4e1c37821a96eaaef`，目标函数与当前
源码完全一致。

动态 `conv2d(stride=2) → sin/mul/add` 图产生真实
`Max(1, FloorDiv(size-3,2)+1)` stride。开启时 loop trace 从 4 维直接合为 1 维，generated
kernel 的 `npu_num_x_nodes=[1]`；关闭时只合并静态 batch/channel 部分，保留 3 个 x node。
两侧首 shape 和动态 replay 都正确，最大误差为 0。

shape-factory 图只使用相同卷积输出公式物化 pointwise 输出，从而隔离多轴 codegen。开启时
生成单轴 kernel，两个正 shape 的最大误差不超过 `5.96e-08`，空输出精确得到
`shape=[2,8,0,0], numel=0`。关闭时生成 3 轴 store，标量 `tmp6` 的 rank `[1]` 无法与
mask rank `[1,47,264]` 广播，预编译阶段所有 config 均失败。该负向结果说明默认 pass 当前
也是下游多轴 codegen 的正确性保护，不是可任意关闭的纯性能开关。

## 4. 性能

性能图使用单通道 3×3、stride-2 动态卷积加 pointwise，确保开关两侧都可编译且实际结构稳定
为 `3→1` 轴。所有 6 个 worker 在同一张 Ascend910B2 上运行；顺序为
`off→on / on→off / off→on`，每个 worker warmup 10、runs 100。设备 Event 是主要结论，host
结果仅保留作 launch-tail 诊断。

| 指标（三轮中位） | 关闭 | 开启 | 开启相对关闭 |
|---|---:|---:|---:|
| device mean | `0.876659 ms` | `0.875514 ms` | `+0.04%` |
| device P50 | `0.873700 ms` | `0.874220 ms` | `-0.06%` |
| device P99 | `0.907000 ms` | `0.900200 ms` | `+0.75%` |
| compile + first run | `20,856.062 ms` | `20,291.183 ms` | `+2.71%` |
| steady peak | `418,934,272 B` | `418,934,272 B` | `0 B` |

三轮 P50 改善率为 `-0.06%/-1.71%/+0.99%`，不能声称稳态加速；P99 第三轮关闭侧有明显
outlier，因此只把三轮中位 `+0.75%` 视为“无持续尾延迟回退”。结构收益和 correctness
收益明确，但端到端图仍由卷积主导。结论是默认保留、性能中性，不为制造收益数字扩大 scope。

## 5. 维护风险

当前实现复制了上游 `_simplify_loops_impl` 的完整方法，上游为 83 行，NPU 安装函数含 patch
逻辑共 105 行。与 P-025 的 wrapper planner 类似，这存在未来上游漂移风险；但本轮定制深入
merge 判定的 sizes、strides 和 substitution 三处，不能在没有等价性证明时机械改成简单前后
委托。当前上游/安装态合同全部通过，因此不创建 P-026。后续 PyTorch 升级时必须重新跑静态
hash、合成合同和负向 shape-factory，不能只看 import 成功。

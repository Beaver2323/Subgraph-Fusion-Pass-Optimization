## 3. 训练重排：移动节点，不改变数学合同

```python
# test/inductor/test_reorder_for_locality_in_training.py:79,128
# issues/REF-reorder-locality-training-native/npu_adapter.py（设备适配）
params, grads, recorder = upstream._train_once(
    'npu', flag_on=mode != 'off', reorder_on=mode != 'master-off'
)
# 社区的 _TwoBranch、输入[8,16] FP32、seed=1234、SGD lr=0.1 均不变。
```

原生测试在一个进程里比较两次训练；项目要求门禁生命周期隔离，所以拆为 OFF/ON 新进程，另跑主开关关闭负例。参数与梯度保存到 CPU 仅用于之后的独立比较，不是训练图 CPU fallback。

```text
源码调用链：_train_once -> torch.compile(fullgraph=True)
 -> AOTAutograd -> post_grad_passes -> reorder_for_locality
 -> NPU lowering/codegen -> forward/backward -> SGD.step
 -> 社区 TestCase.assertEqual 参数及梯度

实际 on/target-1-before.txt：sigmoid -> cos 分支 -> sin_1 分支 -> ...
实际 on/target-1-after.txt： sigmoid -> sin_1 分支及其 matmul_backward -> cos 分支 -> ...
```

节点数量没有减少，但独立分支执行顺序发生变化，这正是 locality 重排的意图；不能仅用算子计数相同否认其生效。GPU 原生也验证 recorder.moved，NPU 本次重复验证该合同。完整 [适配代码及报告](../issues/REF-reorder-locality-training-native/适配报告.md)、[前后 FX/IR/生成代码](../issues/REF-reorder-locality-training-native/evidence/npu-20260911/) 已保留。


只读包装目标 handler，记录 `graph.python_code('self').src` 前后快照并返回原返回值；不是强制匹配。必要调用链为 `原 TestSplitCatAten 方法 -> torch.compile -> post_grad -> 目标 handler -> lowering/codegen -> NPU -> 原数值/counter 断言`。

```python
# torch/_inductor/fx_passes/split_cat.py:1907,1803,2935,1959（行为示意，非逐字源码）
# select-cat：同一输入的完整连续 select + cat -> view(input)
# split-cat：split + 连续 getitem + cat -> input 或单个 slice
# move-view：逐片 view + cat -> 整体 reshape（必要时先 permute）
# normalize-cat：cat(tensors, dim) -> cat(tensors, dim=规范化后的dim)
```

这些都是 lowering/autotune 前的 FX 变换。前三者可能减少拆装和中间操作，最后一项主要提供标准图形，允许后续 pattern 稳定匹配；不能仅因发生改写就宣称有加速。

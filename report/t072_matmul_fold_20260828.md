# T-072：TE-DEC-001 matmul fold 与 P-026 作用域收窄

## 结论

TE-DEC-001 已关闭。原实现把任意高阶/低阶 operand 按 rank 排序后全部强制折叠，虽然保留了
seq-first `[S, B, E] @ [E, N]` 的 MM 路径，但也误覆盖 inner-transpose、stride-0 expand 和
反向 `2D × 3D`。三类扩大作用域的三轮 device P50 中位分别回退 `19.80%`、`23.93%` 和
`49.08%`。

P-026 将 override 收窄到由连续 `[B, S, E]` 执行 `transpose(0, 1)` 形成的精确 stride
合同，仅在原始 LHS 为 3D、RHS 为 2D 且 LHS stride 为
`[E, S*E, 1]` 时补充返回 True；上游已经返回 True 的情况原样保留，其他布局全部委托
上游。最终 verdict 为
`verified-p026-seq-first-fold-retained-broad-scope-regressions-removed`。

## 原实现与生命周期

实际实现位于共享文件
`torch_npu/_inductor/decomposition.py:_override_matmul_should_fold_for_npu`，不是独立的
`triton_experimental/decomposition.py`。experimental backend 激活时，它把
`torch._decomp.decompositions.should_fold` 替换为进程全局 wrapper，并通过
`_npu_fold_3d_2d` sentinel 保证幂等。

该 patch 是 activation-time process-global monkeypatch；当前 backend restore 不恢复
`should_fold`。因此它仍须在 fresh process、单 backend 下使用，这个生命周期问题继续由
P-015 管理，不在 P-026 中扩大修改。

原 wrapper 先按 rank 对 operand 排序，再对任意 `>=3D × <=2D` 返回 True。这比注释中的
seq-first 目标更宽，会同时强制：

- inner matrix transpose，LHS 尾维 stride 不为 1；
- stride-0 expanded LHS；
- 原始顺序为 `2D × 3D` 的反向矩阵乘；
- 未量化的 3D×1D 和高于 3D 的布局。

## 正确性与结构

修复前静态合同 18/18、CPU 合成合同 11/11 通过，确认原实现的真实边界。P-026 候选合同
7/7、产品 UT 4/4 通过；九类 CPU matmul 的值、shape 和 stride 全部一致。

候选真实 NPU 接受 8 个功能 worker、30 次比较：

| 场景 | dtype/模式 | P-026 decision | 生成结构 | 结果 |
|---|---|---:|---|---|
| seq-first | FP32/FP16/BF16 训练 + dynamic | True | MM | 全部精确一致 |
| inner-transpose | FP32 训练 + dynamic | False | BMM | 全部精确一致 |
| expand | FP32 训练 + dynamic | False | BMM | allclose；最大 grad diff `1.5259e-05` |
| reverse `2D × 3D` | FP32 inference + dynamic | False | BMM | 全部精确一致 |
| contiguous control | FP32 训练 + dynamic | upstream True | MM | 全部精确一致 |
| true batched control | FP32 训练 + dynamic | upstream False | BMM | 全部精确一致 |

正式 clean-wheel 又执行 4 个 NPU smoke、10 次比较：FP16 seq-first 训练继续走 MM，三类
回退布局继续走 BMM，全部通过。

早期 `reverse_fp32_off_v1`、`contiguous_fp32_on_v1`、`batched_fp32_on_v1` 和
`p026_inner_fp32` 仅因 audit 对纯 extern 图或旧 on=MM 假设误判，产品数值与结构正确；修正
审计判定后均有接受 worker 取代，聚合不采纳这些旧文件。

## 三轮性能

同一 Ascend910B2、FP16、fresh cache、warmup 10、runs 100，三轮交叉 on/off 顺序。正数为
原强制折叠相对上游的改善，负数为回退。

| 场景 | device P50 三轮 | P50 中位 | peak 中位变化 | compile 中位变化 |
|---|---|---:|---:|---:|
| seq-first | `+9.44/+5.53/+1.47%` | `+5.53%` | `+83.09%` | `-485.49%` |
| inner-transpose | `-19.80/-19.48/-19.81%` | `-19.80%` | `+6.15%` | `-509.12%` |
| expand | `-23.93/-14.53/-28.66%` | `-23.93%` | `+25.30%` | `-497.80%` |
| reverse | `-48.72/-70.17/-49.08%` | `-49.08%` | `-5.82%` | `-647.52%` |

seq-first 三轮 P50 均为正收益但中位未达到 10% latency gate；保留它的主要证据是运行峰值
从 `109,322,240 B` 降到 `18,488,320 B`，固定减少 `83.09%`，属于明确的 resource
benefit。首次编译成本仍约增加 4.85 倍，device mean/P99 和 host tail 也有明显抖动，必须继续
监控，不能把单轮 tail 当作稳定收益。

P-026 性能 smoke 中，三个恢复布局的生成源码 SHA256 与各自上游基线逐字一致，peak 逐字节
一致；候选 P50 相对三轮基线中位为 `+4.89/-1.23/-0.48%`。seq-first 生成源码只差临时
kernel path，规范化 SHA256 均为
`04cc6f249d5790345c67aed284819a20dd6aa2e0e14adcacff7e0d1d85487281`，peak 仍为
`18,488,320 B`。

  独立提供 paired 性能证据；

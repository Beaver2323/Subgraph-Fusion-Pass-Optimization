> 适用入口：[当前优化单元进度表](../report/current_acceptance_unit_matrix.md)。英文代码仅供查旧CSV/JSON；阅读表格不需要记住它们。

## 编译阶段不是完成状态

原列名是`Stage`，不是`State`。它说明优化在编译过程中发生在哪里：

| 原值 | 中文含义 |
|---|---|
| pre_grad | 自动求导前的图优化 |
| joint_graph | 对前向与反向联合图做优化 |
| post_grad | 自动求导之后的图优化 |
| freezing | 推理参数冻结阶段：将可视为常量的参数参与预先计算和折叠 |

T-100的`AU-binary-folding-folded-op`属于最后一类。例如在形状和类型等条件允许时，将`Linear(x, W, b) + c`的常量加法折入偏置，避免每次推理再做这一步加法；乘法等也可折入相应参数。

```python
# 冻结PyTorch 8e86e0a
# torch/_inductor/fx_passes/freezing_patterns.py:37、55～58（节选）
def freezing_passes(gm, aot_example_inputs):
    # ...
    for _ in range(4):
        constant_fold(gm)
        fake_tensor_prop(gm, aot_example_inputs, True)
        binary_folding_pass.apply(gm.graph)
```

因此这个阶段名没有过期，不应改成“已完成”。T-100的完成情况在另一列：**已完成验收**，性能有改善；完整原例及176次Tensor比较等证据见[本批结果](../results/current/T-100/)。

## 测试范围验收（原“覆盖”列）

| 原值 | 现在显示 | 实际含义 |
|---|---|---|
| base-contract-not-yet-closed | 原定测试范围尚未验收完成 | 还没形成正式对比结论。可能已经跑过甚至功能通过，但修复、审核或性能等工作尚未完成；不能当作完全没测过。 |
| duplicate-noncounting | 重复记录，不重复计数 | 和另一个单元是同一验收范围，仅保留别名/补证。例如T-112并入T-084、pattern17并入15，不再加分母和完成分子。 |
| fully-covered | 已登记范围已完成验收 | 已有正式结论且没有登记中的新增测试范围待完成。不是所有dtype/shape都支持，不代表性能一定提升，也不消除单列的历史再认证限制。 |

“测试范围验收完成”和“与社区完全一致”不是一回事：一个单元可以完成验收，但结论是部分一致、性能回退，或符合产品设计的明确关闭。

## GPU对照证据（原Reference列）

这里的对照指：先在GPU上运行社区测试，确认社区预期及目标优化，作为后续NPU验证的依据；不是NPU结果。

| 原值 | 现在显示 | 实际含义 |
|---|---|---|
| frozen-reference-valid / valid-reference-frozen | GPU对照已确认，范围已确定 | 两种历史写法，阅读时合并理解；有效对照已纳入确定的验收范围。“冻结”是确定范围，不是任务暂停。 |
| valid-reference-suite | GPU对照整批测试有效 | 来自批次汇总。在当前表中这些单元也已确定验收范围，但这串代码本身只描述GPU批次有效，不能独立推出NPU通过。 |
| gpu-contract-reviewed-awaiting-npu | GPU对照已审核，NPU验收未完成 | GPU侧依据够用，剩余是NPU工作；即使NPU已经跑过失败，也仍可能显示此值，不应理解成NPU从未执行。 |
| gpu-validated-duplicate-contract | GPU补证有效，与已有单元重复 | 保留证据，不新增独立验收单元。 |
| native-passed-different-target-observed | 原测试通过，但命中的是其他优化 | 不能证明本编号优化有效，须补充精确目标证据或确认重复关系。 |
| native-passed-target-attribution-pending | 原测试通过，尚未确认命中目标优化 | 尚未确定究竟触发哪条优化，不能拿测试退出成功代替目标命中证据。 |

## 其余列怎么读

- NPU执行与数值/正确性：目标匹配失败不一定是数值错；“尚无结果”也不是“通过”。随机测试若没有比较输出/梯度，报告必须明确未验证的范围。
- GPU与NPU对比：区分原有功能正常、修复后新增支持、符合产品设计的差异、真实问题。旧批次有把性能结论写入这列的情况，仅作中文翻译，不重写原证据。
- 修复情况：安装环境验证通过不等于社区PR已合入；验证范围以对应修复报告为准。
- 社区一致性：区分已测范围一致、底层实现不同、部分一致、需要修复和尚待复核，不能从测试通过自动推成全域一致。
- 性能：区分改善、回退、无明显变化、效果混合、明确免测及尚未测量。无法单独归因且经用户接受的结项不计收益，也不是关闭免测。
- 完成情况：这是项目进度。历史批次“已记录功能对比结论”仍须结合单列的性能和严格历史再认证限制；不要看编译阶段来判断是否完成。

以后面向人的进度表使用中文列名与说明；CSV/JSON中的稳定代码继续用于自动校验，不再直接充当阅读版用语。

## 测例意图与来源

在freezing后，把Linear输出上的常量二元运算折入weight/bias，减少每次推理的二元kernel。
原方法为冻结PyTorch `test/inductor/test_binary_folding.py::FreezingGpuTests.test_linear_binary_folding_cuda`。
GPU旧run重压缩包已完整核验；NPU先执行原入口失败，再按[适配报告](适配报告.md)只适配类发现/device。

```python
# PyTorch test/inductor/test_binary_folding.py:227，逻辑节选
x = self.linear(x)
return self.op(x, 2.0 if self.use_scalar else self.tensor)
# 合法广播：binary_folding counter == 1
# [4,32]/[4,1]逐batch常量负例：counter == 0
# 数值：atol=5e-5，rtol=5e-6，不放宽。
```

## 结果与GPU/NPU对比

1个原方法、零skip；176次FP32输出比较通过，160次counter=1，16次counter=0，160次folded_op实际改图。
176份debug output_code中，120份调用NPU extern addmm、56份调用NPU extern mm；
16个非法广播负例保留额外Triton二元计算。静态调用/设备扫描未见CPU迁移；全文保留以供复核。
GPU和NPU当前合同一致：合法常量折叠、非法广播保留原二元运算。尚未据此签发性能或全项目闭环。

## 学习时需注意的原社区覆盖边界

原循环名为use_bias=True/False，但内部构造`LinearOp(3,32,self.device)`并未把它传给nn.Linear，
所以不能由循环变量宣称实际覆盖bias=False。这是冻结社区方法的覆盖缺口，适配器没有偷偷改变原方法。
176组合=64个2D正例+96个3D正例+16负例；没有BF16/FP16或梯度合同。

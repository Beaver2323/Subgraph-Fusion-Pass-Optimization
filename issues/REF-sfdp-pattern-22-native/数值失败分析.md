## 结论与范围

安装态 `triton_experimental` 的原社区方法在接受已审查的SDPA数学展开后，
第一组FP32输入就触发原数值断言：3772/4096元素超差，最大绝对差160767568.0。
发生在返回tuple的第0项（attention输出）；本轮没有完成后续batch=1和mask转置分支。
这不是“目标未命中”，也不是仅凭CUDA/NPU生成符号不同判失败：本编号已经改图1次，
随后真实NPU输出不满足原eager对照。如此量级的差异不能按普通舍入误差放宽容差。

## 三种子逐kernel定位：行最大值开始出错

[原件、诊断器快照、实际重放生成代码](evidence/kernel-diagnostic-20260914T231625/)已入库。
物理NPU5、安装态同后端；种子20260914/15/16，每个种子比较8个kernel和最终输出。
Q/K重排、mask判定均正确；行最大值kernel每个种子都244/256元素不符，最大绝对差分别
21.3334、13.2813、13.4208。exp之和随后也错误；归一化kernel对其**实际错误输入**计算一致，
不代表最终softmax正确。返回K/V都一致，最终attention输出严重超差。

```python
# 归档generated_source.py:368附近，行最大值kernel。
# 共享mask的加载只含x1，不含x2；因此该值实际形状是[1, real_block_x1, 2]。
_es_full1 = tl.load(in_ptr1 + 2*x1 + _es_lane1, x1mask, eviction_policy='evict_last')
tmp1 = extract_slice(_es_full1, [0,0,0], [real_block_x2, real_block_x1, 1], [1,1,1])
```

疑点：生成器为所有加载复用输出tile尺寸，但mask在x2上是singleton，不能把切片首维取成
`real_block_x2`；应该先保留1，由后续运算广播。同样写法在amax与exp-sum中各两处。
此外从偏移1加载额外lane存在越界读取风险，需分别审查，不因切片首维候选有效就认定尾界也安全。

```text

```

隔离实验仅修改**该轮生成代码副本**四处mask切片首维为1，保持调度/算子/其他加载不变。
[候选源码及三种子结果](evidence/broadcast-shape-candidate-20260914T233440/)现已入库：
三个种子的8个kernel对照、最终attention输出和返回K/V全部`mismatch=0, max_abs_error=0`。
对本轮图，这一反事实实验确认共享mask广播维度被错误扩大是首处分歧的原因；
它不是安装态修复，也没有证明原例全部输入分支或整个select优化普遍安全。

## 通用候选设计（原合同及邻接隔离验证已通过）

```python
# runners/attention_select_slice_candidate.py：进程内候选，不写site-packages。
# 发射extract_slice时按每个实际load的shape取外维，不再共用输出tile尺寸。
sizes = [1 if s == inner_slot else full_value.shape[s] for s in range(ndim)]
# 拓宽lane加载额外绑定实际静态存储长度；offset布局/动态未知边界保留原load。
mask = original_mask & (offset + lane >= 0) & (offset + lane < storage_size)
```

第二项保护处理从偏移1等位置拓宽会越界的独立风险，不用“最后只取lane0”掩盖实际越界读取。
原strided-slice分支保持不变；未知边界保留原加载，绝不跳过原算子。源码锚点不符会拒绝应用，
新结果明确`isolated_codegen_candidate=true`；阶段收件、正式归档及性能gate均拒绝将其冒充安装态。

# Pattern 22：共享 mask 的 select-load 广播错误与隔离修复

> 更新时间：2026-09-15 00:25 CST（UTC+08:00）。结论：原社区全方法及三个邻接通过；隔离候选未部署，不计正式修复或性能完成。

## 1. 问题是什么，修改在哪一层

pattern 22 把 `softmax(QKᵀ + mask) @ V` 及返回 K/V 的图改成 SDPA。
GPU 原例有效；NPU `triton_experimental` 已发生本编号改写，但数学展开生成的行最大值错误，
导致首组 FP32 输出 3772/4096 元素超差，最大绝对差 160767568。
根因不在“是否匹配”，而在后续 codegen 将共享 mask 的 singleton 外维错误扩为输出 tile 外维。

```text
# 冻结 PyTorch 与本轮安装态 NPU 的实际路径
test/inductor/test_fused_attention.py:1387 _test_sdpa_rewriter_22
 -> _check_common -> torch.compile
 -> joint graph 的 _sfdp_pattern_22 replacement -> SDPA
 -> NPU 数学展开 -> bmm / safe_softmax / bmm
 -> torch_npu/_inductor/triton_experimental/codegen/triton.py
    _maybe_record_select_lane_load -> _maybe_rewrite_select_lane_load
 -> output_code.py 行最大值 / exp-sum kernel -> 原 eager 数值断言失败
```

详细原失败栈与三种子逐 kernel 定位见[数值失败分析](数值失败分析.md)。这份报告包含足够的关键代码，
不要求读者先读其他报告；完整原件仍从链接定位。

三种子生成副本反事实对照只改四处切片首维，已把 8 个 kernel 对照及最终输出误差归零，
因此广播错误已有直接因果证据。边界保护另处理偏移 1 时拓宽额外 lane 的越界风险，
不是声称越界已被证明是原输出超差的唯一原因。

候选不识别本 pattern 编号或固定形状；仅在进程内替换两个 codegen 方法。
未知静态存储长度、非零 layout offset、无法拆解的指针表达式保持原加载，间接内维不改；
strided-slice 的 Case B 仍走原分支。锚点变化则拒绝应用，不猜测修改产品源码。

## 1. 修复目标

保护 `fp32/bf16-autocast + M=2048,K=N=2` 的 forward/backward 合同，阻止 NPU 进入 upstream
small-MM pointwise lowering，恢复可靠 extern mm。该修复不启用 T-077 的 `decompose_mm` 目标 pass，
也不改变它的 device/shape guard。

详细首个分歧、必要调用链和非根因边界见 [`根因分析.md`](根因分析.md)。

## 2. 产品修复代码框

补丁位置：`torch_npu/_inductor/triton_experimental/overrides.py`。仓库保存的可审阅补丁为
[`backend_fix_dfbcc25.patch`](backend_fix_dfbcc25.patch)。

```python
# torch_npu/_inductor/triton_experimental/overrides.py
def _disable_small_mm_pointwise_on_npu():
    from torch._inductor.kernel import mm as mm_kernel

    current = mm_kernel._use_small_mm_pointwise
    if getattr(current, "_torch_npu_small_mm_guard", False):
        return

    @functools.wraps(current)
    def npu_safe_small_mm_pointwise(m, k, n, layout):
        if layout.device.type == "npu":
            return False
        return current(m, k, n, layout)

    npu_safe_small_mm_pointwise._torch_npu_small_mm_guard = True
    mm_kernel._use_small_mm_pointwise = npu_safe_small_mm_pointwise


def apply_npu_overrides():
    ...
    _disable_small_mm_pointwise_on_npu()
    ...
```

这里 patch `torch._inductor.kernel.mm` 模块已经导入的符号，而不是只修改
`mm_common._use_small_mm_pointwise`，因为 `tuned_mm` 在该模块中直接解析前者。幂等标记防止多次激活
后形成 wrapper 链。

## 3. 修复前后路径

```text
修复前
aten.mm
  → tuned_mm
  → _use_small_mm_pointwise(NPU) == True
  → unsqueeze/mul/sum
  → triton_unk_fused_mm_0/1
  → left-grad 错误

修复后
aten.mm
  → tuned_mm
  → npu_safe_small_mm_pointwise(NPU) == False
  → 跳过 pointwise early-return
  → extern mm
  → forward/left-grad/right-grad 正确
```

这说明修复改变的是 lowering 分支，不是 post-grad FX pattern。验证时仍要求
`counters["inductor"]["decompose_mm"] == 0`。

## 4. 单元测试代码框

候选同时验证 NPU-only 和幂等性：

```python
# test/_inductor/test_triton_experimental_regressions.py
def test_small_mm_pointwise_is_disabled_only_for_npu(self):
    original = mock.Mock(return_value=True)
    with mock.patch.object(upstream_mm, "_use_small_mm_pointwise", original):
        overrides._disable_small_mm_pointwise_on_npu()
        guarded = upstream_mm._use_small_mm_pointwise

        self.assertFalse(
            guarded(2048, 2, 2, SimpleNamespace(device=torch.device("npu")))
        )
        self.assertTrue(
            guarded(2048, 2, 2, SimpleNamespace(device=torch.device("cuda")))
        )

def test_small_mm_pointwise_guard_install_is_idempotent(self):
    ...
    overrides._disable_small_mm_pointwise_on_npu()
    first = upstream_mm._use_small_mm_pointwise
    overrides._disable_small_mm_pointwise_on_npu()
    self.assertIs(upstream_mm._use_small_mm_pointwise, first)
```

if args.apply_candidate_small_mm_guard:

adapter 注入是修复验证工具，不是正式产品实现；正式实现是前述 overrides 补丁。

## 7. 性能与合入结论

correctness 修复和目标 `decompose_mm` 性能候选是两件事：

- 本补丁保留，因为它消除了真实梯度错误；
- 另行构造的合法 NPU ON 路径在相同 backend 下 Event p50/p99 回退 `11.38%/1.62%`，所以没有
  启用目标分解，继续保留 device guard；
- 不能因目标优化性能回退而撤销 correctness guard，也不能把 extern 修复写成性能优化。

候选当前结论是 `verified-not-merged`。只有补丁正式推送/合入、安装正式构建并重跑同一六变体后，
才能把 `regressions/known_issues.yaml` 中的记录迁移到 fixed。

### Adapter 首轮：`FAIL`（非目标全局 counter 差异）

- 执行时间：2026-09-02 02:47–02:48 CST（UTC+08:00）。
- 设备：执行前唯一无进程的物理 NPU 7，在可见子集中为 `npu:0`。
- 结果：1 个 unittest 实例进入 test body，在第 3/4 组输入断言失败；无 skip，无编译异常。
- backend 验真：`_InductorNpuRegistry._loaded_backend=triton_experimental`。
- 正例 1（same-K）：数值一致，counter `1/3`，变换后 FX 只含 `mm_plus_mm`，`output_code.py` 调用 `extern_kernels._mm_plus_mm`。
- 正例 2（different-K）：数值一致，counter `1/3`，变换后 FX 含 `mm_plus_mm`；生成代码按合同回退为两个 `extern_kernels.mm` 加 NPU Triton pointwise add。
- 负例 1（输出形状不匹配）：数值一致，变换后 FX 保留 `mm + mm + add`，生成代码为两个 `extern_kernels.mm` 和 Triton add，未出现目标 `mm_plus_mm`。
- 失败点：GPU reference 该负例的全局 counter `1/2` 来自另一个非目标 add-mm pattern；NPU 为 `0/0`。这不表示目标负向 gate 失败。
- 未执行项：继承方法在第 3 组抛出断言，第 4 组尚未运行。

### Adapter 第二次启动：`ENV_BLOCKED`（bootstrap 顺序）

### Adapter 第三次启动：`ENV_BLOCKED`（通用 bootstrap 与 backend loader 不兼容）

2026-09-02 02:53 使用启动前无进程的物理 NPU 3。按通用 CUDA 测例迁移模板加载
`transfer_to_npu` 后，该模块改写了 `get_gpu_type`；当前 installed torch_npu 的
`triton_experimental` loader 在 `patch_is_gpu()` 中调用 `get_gpu_type.cache_clear()`，
因被替换函数不再带该属性而报 `AttributeError`。本轮同样未进入编译。

本 case 已显式使用 `device=npu`，不需要 CUDA API 转译；且首轮不加该通用迁移层时
已完成三组真实 NPU 编译。因此后续回到更小的 `import torch_npu` + 显式
NPU device/backend 注入，保留 `TORCH_COMPILE_DEBUG=1` 与产物核验，不再使用会污染
backend registry 的 `transfer_to_npu`。

## 初步判断

直接入口是上游 GPU 测试路由层未把 PrivateUse1/NPU 纳入 `HAS_GPU` 的入口阻断，
不是 pattern 实现失败。Adapter 首轮进一步证明两个正例都命中目标合同，
第一个负例也正确排除目标合同；失败仅是 GPU 上非目标 pattern 的 suite-global counter
不能直接移植到 NPU。Manifest 已显式要求负例使用目标 counter/codegen 复核，因此不修改图和 shape，
只将 NPU 负例断言收窄为“生成图/代码中不得出现 `mm_plus_mm`”。

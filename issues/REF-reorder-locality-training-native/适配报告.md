## 2. 最小适配

```python
# issues/REF-reorder-locality-training-native/npu_adapter.py
params, grads, rec = module._train_once(
    'npu', flag_on=args.mode != 'off', reorder_on=args.mode != 'master-off'
)
```

完整复用冻结 commit `8e86e0a23e3679c2bf3406cf0837fcb6297a5d9b` 中的 `_TwoBranch`、`_train_once`：两路 16×16 参数矩阵、8×16 FP32 输入、seed=1234、SGD lr=0.1、forward/backward/step 都不变。只传 NPU 设备并用官方 torch_npu.testing 适配测试框架。

由于项目要求 OFF/ON 新进程，原生单个测试里的两个 `_train_once` 被拆开；结果保存到 CPU 仅用于跨进程比较，不是计算路径的 CPU fallback。比较仍使用社区 TestCase.assertEqual，不能只比较 loss。主开关关闭另用 `master-off` 新进程执行。只读 Recorder 保存重排前后 FX，不改变 handler 返回值。

## 4. 结果与边界

`product_gate_bypassed=false`；未修改 PyTorch/torch_npu 产品源码或放宽精度阈值。OFF、ON、master-off 已分别在物理 NPU 2、Pass Python 3.11.15 环境运行，实际后端均为 `triton_experimental`；torch 为上述冻结 commit，torch_npu 为 `2.14.0a0+git83cc452`，CANN 9.0.1。

ON 调用目标 2 次，前向图未移动、反向图发生移动；OFF 与 master-off 都是零调用。跨进程复用了社区 TestCase.assertEqual：两个参数及其梯度的 ON/OFF、master-off/OFF 比较全部通过，8 项最大绝对误差均为 0。这里比较的是训练状态，不是每个中间张量的逐位合同。

结果在 [训练核验 JSON](../../results/current/T-087/npu_training_review.json)，三臂的 FX、IR、生成代码及目标前后图在 [证据目录](evidence/npu-20260911/)。该目录中的 CPU tensor 保存/加载只用于跨进程对照，不在训练计算路径内。

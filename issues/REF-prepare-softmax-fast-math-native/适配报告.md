# T-080 Prepare-Softmax NPU 适配与产品边界报告

> 更新时间：2026-09-07 20:20 CST（UTC+08:00）
>
> 后端：仅 `triton_experimental`

## 1. 原生阻断

3 个 GPU 社区入口在 NPU 上受 GPU class/启动条件阻断。继续显式运行原方法后，upstream
`prepare_softmax_extra_check` 还只接受 `cuda/xpu`。这是 generic upstream device guard，不等同于
NPU 产品显式关闭，所以只能先做单独评审的测试态能力探针。

```python
# torch/_inductor/fx_passes/post_grad.py:490-520
def prepare_softmax_pattern(x, dim): ...
def prepare_softmax_replacement(x, dim):
    xmax, xsum = prepare_softmax_online(x, dim)
    ...
```

## 2. 最小适配

`runners/t080_npu_case.py::install_prepare_softmax_probe` 扫描已注册的 post-grad pattern，只替换闭包
中名字为 `prepare_softmax_extra_check` 的 cell；traced pattern、replacement、kwargs 和 shape checks
保持不变。该探针不进入产品源码。

```python
# runners/t080_npu_case.py
post_grad.lazy_init()
...
if getattr(original, "__name__", None) == "prepare_softmax_extra_check":
    def observed(match, _check=original):
        if match.kwargs["x"].meta["val"].device.type == "npu" and enabled:
            return True
        return _check(match)
    cell.cell_contents = observed
```

strict-signed-zero case 的旁路 compiled `amax` 会先在 Triton-Ascend
`ConvertLinalgRToBinary` 报未实现。适配只把这个参考计算换成 eager amax 位级 oracle，以便继续检验
目标图；没有宣称 amax lowering 已修复。

## 3. 必要调用链

```text
run_t080_softmax.sh
  -> run_t080_case.py --adapter --enable-softmax-probe
  -> install_prepare_softmax_probe
  -> 原 fast-math / signed-zero / perf 方法体
  -> post_grad register_replacement
  -> FX 出现 prims.prepare_softmax_online.default
  -> torch_npu lowering_fallback_list
  -> generated code 外部调用 torch.ops.prims.prepare_softmax_online.default
  -> 无 online_softmax_reduce Triton kernel
```

## 4. 结果与边界

- 探针 3/3 进入目标结构；fast-math 与默认 perf 数值通过，signed-zero 的位级 oracle 通过。
- GPU 会生成 online kernel；NPU 只完成结构 replacement，产品 lowering 明确 fallback。
- 这属于 `EXPECTED_PRODUCT_DIVERGENCE`，不是端到端优化生效。
- `product_gate_bypassed=false`；没有移除
  `torch_npu/_inductor/lowering_fallback_list.py` 中的显式关闭。
- 因没有合法同后端 ON 路径，性能为 `PERF_EXEMPT`。详细对照见
  [`../../docs/T080_RESULT_AND_LEARNING_GUIDE.md`](../../docs/T080_RESULT_AND_LEARNING_GUIDE.md)。

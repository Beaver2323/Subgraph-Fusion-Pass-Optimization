## 1. 先区分症状与原因

安装态原方法在第一轮训练分支的 `fuse_attention >= 1` 断言失败，实际0；推理分支只观察到
`_sfdp_pattern_1_inference`。推理删除dropout后命中邻接编号不是pattern 3成功。
本方法设置`has_dropout=True`且没有覆盖默认比较开关，本轮Tensor比较为0；
这是匹配合同失败，**当前证据不能宣称额外发现数值错误或证明数值正确**。
原失败栈及实际执行路径见[安装态基线复核](安装态基线复核.md)。

## 3. 所处调用位置与避免误判

```text
原社区 dot_prod_attention(dropout=0.4, training=True)
  → NPU decomposition 生成 _npu_dropout / packed mask
  → AOT joint graph → attention预生成训练pattern尝试匹配
  → 不满足匹配合同，fuse_attention=0
  → 后续softmax稳定性pass、lowering/codegen
  → NPU执行后触发原counter断言失败
```

生成的最终FX中还可见isfinite/where等稳定性节点；它们出现在attention匹配后的上游joint pass，
不能从最终图倒推出“这些节点抢先破坏匹配”。完整joint训练匹配还包含softmax和matmul反向图，
此处仅确认dropout前提不兼容，不把pattern 1的所有反向差异直接当成本例已实测证据。

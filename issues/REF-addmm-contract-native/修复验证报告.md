## 1. 候选目标

把 add+mm→addmm 从“backend 激活时不可逆关闭”改成“默认允许 upstream guard、运行期可显式关闭”的
live gate。当前安装态 `disable_addmm_fusion=True` 仍是 T-076 正式基线；本报告只说明 P-018 候选
为什么可合入，不宣称它已进入正式产品。

## 2. 候选代码框

默认配置只改变一个产品决策：

```python
# torch_npu/_inductor/triton_experimental/config.py:132
# upstream validity check 与 NPU extern addmm lowering 已通过 P-018 合同矩阵。
disable_addmm_fusion: bool = False
```

gate wrapper 必须始终安装并在每次 pattern match 时读取 live config：

```python
# torch_npu/_inductor/triton_experimental/fx_passes.py:541
def _disable_addmm_fusion_pass():
    from torch._inductor.fx_passes import post_grad

    installed = 0
    seen_entries = set()
    for entries in post_grad.pass_patterns[2].patterns.values():
        for entry in entries:
            entry_id = id(entry)
            handler = getattr(entry, "handler", None)
            if (
                entry_id in seen_entries
                or getattr(handler, "__name__", None) != "addmm"
            ):
                continue
            seen_entries.add(entry_id)
            if not getattr(
                entry.extra_check,
                "_torch_npu_addmm_gate_installed",
                False,
            ):
                original_check = entry.extra_check

                def gated_extra_check(match, _original_check=original_check):
                    if ncfg.disable_addmm_fusion:
                        return False
                    return _original_check(match)

                gated_extra_check._torch_npu_original_extra_check = original_check
                gated_extra_check._torch_npu_addmm_gate_installed = True
                entry.extra_check = gated_extra_check
                installed += 1
```

关键设计点：

- `False` 时委托 upstream `is_valid_addmm_fusion`，不是无条件匹配；
- `True` 时只关闭 handler 名为 `addmm` 的两个 entry；
- marker 保证重复激活不叠加 wrapper；
- default argument 捕获每个 entry 自己的原 check，避免 Python closure 晚绑定；
- 保存 `_torch_npu_original_extra_check` 便于审计和恢复。

## 3. 修复前后调用路径

```text
安装态基线（disable=True）
mm + add
  → post-grad addmm entry
  → extra_check 恒 False
  → 不改写
  → extern mm + NPU Triton pointwise add

P-018 默认（disable=False）
mm + add
  → post-grad addmm entry
  → gated_extra_check
  → upstream is_valid_addmm_fusion
  → addmm handler
  → aten.addmm
  → NPU extern addmm

P-018 显式 opt-out（导入后 disable=True）
mm + add
  → gated_extra_check 实时读取 True
  → 不改写
  → extern mm + NPU Triton pointwise add
```

完整必要调用链及首个分歧见 [`根因分析.md`](根因分析.md)。

## 4. 功能验证

冻结社区合同的精确复验结果：

| 逻辑 case | 期望 counter | P-018 | 生成路径 |
| --- | ---: | ---: | --- |
| matrix bias，两种 operand order | `2/4` | `2/4` | 两个 `extern_kernels.addmm` |
| vector bias，两种 operand order | `2/4` | `2/4` | 两个 `extern_kernels.addmm` |
| non-expandable bias | `0/0` | `0/0` | mm + add |
| batched bias | `0/0` | `0/0` | mm + add |
| Python scalar | `0/0` | `0/0` | mm + add |
| dynamic symbolic scalar | `0/0` | `0/0` | 两路 extern mm + dynamic Triton add |

扩展 capability 矩阵 `11/11` 通过，覆盖 FP16/BF16/FP32、row/full/vector bias、unaligned、真实
transpose、dynamic replay、forward/backward、scalar 和 mixed-dtype 负例。P-018 复用现有 NPU extern
addmm lowering，没有 CPU fallback。

## 5. live gate 与幂等验证

无设备 source probe 覆盖：

```text
默认 False
  → 原 upstream checks 仍决定匹配
导入后设置 True
  → 两个 entry 均拒绝
恢复 False
  → 两个 entry 重新委托各自 original check
重复调用 installer
  → 不增加 wrapper 层
```

这比“只把默认 True 改为 False”多解决了一个真实生命周期缺口：backend activation 发生后，调用方仍
可以 opt out。只修改默认值而保留旧的早返回/覆盖逻辑，无法提供该性质。

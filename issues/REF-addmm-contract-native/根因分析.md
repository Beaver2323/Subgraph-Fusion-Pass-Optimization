# T-076 post-grad addmm 产品 gate 差异分析

> 更新时间：2026-09-07 09:50 CST（UTC+08:00）
>
> PyTorch：`release/2.14@8e86e0a23e3679c2bf3406cf0837fcb6297a5d9b`
>
> torch_npu 基线：`master@83cc452480c3546fd5cccf853bfe3a360ce9dbfc`
>
> 后端：`triton_experimental`；设备：Ascend910B2

## 1. 结论与分类

T-076 post-grad addmm 没有 NPU correctness 回归。GPU 上 matrix/vector bias 的两种 operand order 均
把 `mm + add` 改写为 `aten.addmm`，当前 NPU 安装态则保持 `mm + add`；两侧数值都正确。

首个分歧在 torch_npu 的显式产品配置 `disable_addmm_fusion=True`。后端激活时，它把两个 upstream
addmm pattern entry 的 `extra_check` 关闭，所以 NPU 正例 counter 为 `0/0`。正式基线应分类为
`EXPECTED_PRODUCT_DIVERGENCE`，不是“pattern 故障”。

P-018 是经过独立评审和验证的 capability/gate 调整候选：默认允许 upstream validity check 决定是否
融合，同时保留运行期显式 opt-out。它是候选产品变更，不应改写安装态基线结论。

## 3. upstream pattern 的意图与 guard

两个 operand order 共用 `is_valid_addmm_fusion` 和同一个 handler：

```python
# torch/_inductor/fx_passes/post_grad.py:1983
def is_valid_addmm_fusion(match):
    mat1, mat2 = match.args
    inp = match.kwargs["inp"]

    if not (
        isinstance(inp, torch.fx.Node)
        and isinstance(inp.meta["val"], torch.Tensor)
    ):
        return False

    mm_shape = mat1.meta["val"].shape[0], mat2.meta["val"].shape[1]
    if not is_expandable_to(inp.meta["val"].shape, mm_shape):
        return False
    if (
        inp.meta["val"].dtype != mat1.meta["val"].dtype
        or inp.meta["val"].dtype != mat2.meta["val"].dtype
    ):
        return False
    return not should_prefer_unfused_addmm(match)

# torch/_inductor/fx_passes/post_grad.py:2013
@register_graph_pattern(
    CallFunction(aten.add, CallFunction(aten.mm, Arg(), Arg()), KeywordArg("inp")),
    pass_dict=pass_patterns[2],
    extra_check=is_valid_addmm_fusion,
)
@register_graph_pattern(
    CallFunction(aten.add, KeywordArg("inp"), CallFunction(aten.mm, Arg(), Arg())),
    pass_dict=pass_patterns[2],
    extra_check=is_valid_addmm_fusion,
)
def addmm(match, mat1, mat2, *, inp):
    match.replace_by_example(
        lambda inp, mat1, mat2: aten.addmm(inp, mat1, mat2),
        [inp, mat1, mat2],
    )
```

因此 P-018 不需要新写 pattern，也不能删除 upstream 的 tensor、broadcast、dtype 和
`should_prefer_unfused_addmm` guard。

## 4. 安装态 gate 与首个分歧

安装态配置为：

```python
# torch_npu/_inductor/triton_experimental/config.py
disable_addmm_fusion: bool = True
```

旧 gate 在 backend activation 时直接中和已注册 entry：

```python
# torch_npu/_inductor/triton_experimental/fx_passes.py::_disable_addmm_fusion_pass
if not ncfg.disable_addmm_fusion:
    return

for entries in post_grad.pass_patterns[2].patterns.values():
    for entry in entries:
        if getattr(entry.handler, "__name__", None) == "addmm":
            entry.extra_check = lambda match: False
```

这解释了为什么导入后把 config 改回 False 也无效：原 `extra_check` 已被覆盖，旧实现既没有保存它，
也没有恢复路径。

本项没有 exception traceback；安装态输出正确，只是目标优化被 gate 拒绝。由 backend activation、

## 6. 修复与非修复边界

需要解决的是 gate 生命周期：默认 capability 已验证可用时允许原 check 工作，并让显式 opt-out 在
backend 导入之后仍生效。无需且禁止：

- 修改 PyTorch 通用 `is_valid_addmm_fusion`；
- 放宽 scalar/non-expandable/batched/mixed-dtype 负例；
- 新增 addmm lowering 或手写 Triton GEMM；
- 把 P-018 候选结果冒充当前安装态已经开启；
- 用 default/DVM/MLIR 性能结果替代 `triton_experimental`。

候选实现、调用路径和验证矩阵见 [`修复验证报告.md`](修复验证报告.md)。

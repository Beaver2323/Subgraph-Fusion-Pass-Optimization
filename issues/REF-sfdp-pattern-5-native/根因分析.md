## 测试目的

验证 `softmax(QKᵀ / scale + mask) @ V` 在不同 bool mask、scale 和 checkpoint 情况下改写，并与 NPU eager 对齐。原方法六次 `_check_common`、推理/训练合计 12 个分支，30 次输出/输入梯度比较；本例 dtype 全部为 FP32。

## 根因类型与判定依据

NPU 训练图匹配行为不一致。旧安装态首次推理已命中，首次训练 `fuse_attention=0`；不是输出先超差。原栈见[安装态复核](安装态基线复核.md)。

## NPU 能力匹配评估

保留 NPU matmul_backward 和 softmax 梯度分解后重新生成原 search 的训练注册，完整原方法通过。实际 18 份生成图：有带 mask 的 BMM/safe-softmax 数学展开及对应反向，也有全零 mask 简化后的 NPU fusion-attention/grad-v3。不能把所有分支称为 fused-attention kernel，也不能由改写推导性能收益。

本编号实际 8 次改写（4 training、4 inference）。全零 bool mask 的普通/checkpoint 分支退化为 pattern 1，各有两次 training/inference，共另外 4 次改写，明确不计成本编号。原 Tensor 比较 30/30，零 skip。

```python
# test/inductor/test_fused_attention.py:373，sfdp_pattern_5_v2 节选
attn_mask = torch.zeros(query.size(-2), key.size(-2), dtype=torch.bool, device=query.device).bool()
attn_weight = torch.softmax((query @ key.transpose(-2, -1) / math.sqrt(query.size(-1))) + attn_mask, dim=-1)
# 该全零 mask 可以被消去，允许由 pattern 1 承载，而不是补造 pattern 5 命中。
```

## 修复理由

仅修复 experimental 的训练注册与实际分解不一致，不恢复 FMA，不删 mask/dtype/device guard，不修改冻结 PyTorch。按实际分解追踪会增加首次注册开销，本轮稳态性能不测该开销。

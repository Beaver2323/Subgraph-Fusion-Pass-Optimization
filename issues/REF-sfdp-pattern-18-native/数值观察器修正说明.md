## 1. 旧记录的零意味着什么

旧原例1/1、零skip、四次本编号改写，但`tensor_assertions=[]`。
源码复核确认它**有数值断言**：原方法返回三元tuple，旧观察器只记录顶层两个参数均为Tensor的`assertEqual`，
因此漏记了容器内部比较。不能将此零解释为“原社区没有精度检查”。

```python
# test/inductor/test_fused_attention.py:1122起，_test_sdpa_rewriter_18（节选）
return attention_output, restored_key, restored_value
# 同方法四次_check_common：batch 4/1 × scale原值/偏移0.1
self._check_common(..., has_dropout=False, check_train=False)
# 同文件:137，执行原assertEqual(tuple, tuple)，内部比较Tensor叶子。
self.assertEqual(result1, result2, atol=atol, rtol=rtol)
```

这里预期是四次容器输出比较、共12个Tensor叶子；不是12个独立测例，也不包含输入梯度。
该数量来自源码推导，**旧原件没有12条叶子运行记录，不追写旧JSON**。

## 2. 修正方式

```python
# runners/attention_community_npu.py: NpuCase.assertEqual
result = super().assertEqual(a, b, *pos, **kw)  # 原比较先成功
for path, left, right in passed_tensor_pairs(a, b, torch.Tensor):
    # 只记录元数据与容器路径，不再次计算或修改容差。
    record_passed_tensor_leaf(path, left, right)
```

新增递归深度保护，避免原实现递归调用`self.assertEqual`时重复计数；原比较失败则不记录成功叶子。
新运行标记`tensor_observer_version=2-container-leaves-after-original-assertion`，各轮保留自己的harness快照及SHA。
这只是测试观察器修正，不涉及NPU产品实现、输入或数值容差。

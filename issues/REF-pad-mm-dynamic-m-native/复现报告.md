## 执行结果

### 原生直接入口：`NO_TESTS`

- run root：`/home/z50063656/tmp/t076-npu-results/REF-pad-mm-dynamic-m-native/direct-20260902T033300+0800`。
- 物理 NPU 2 在启动前为 `No running processes found`。
- 进程退出码 0，但日志只有 torch_npu 的 torchair warning，没有 unittest 统计。
- 原因：文件主入口只在 `HAS_GPU_AND_TRITON` 为 true 时调用 `run_tests()`；当前上游
  `GPU_TYPE`/`HAS_GPU_AND_TRITON` 不把 NPU 计入 GPU 路由。
- 这不是用例 PASS，也不是用例内部 skip。

### Adapter 首轮：`FAIL`（lowering 候选配置阻断）

- run root：`.../adapter-20260902T034000+0800`；启动前物理 NPU 2 无进程。
- adapter 保持上游 `max_autotune_gemm_backends=TRITON`，未绕过产品 gate。
- backend 加载后 pad-mm 已关闭，原始 `aten.mm` 进入 lowering；当前 NPU 对该
  dynamic/strided fp32 mm 没有有效 Triton choice，报：

```text
NoValidChoicesError: No choices to select. Provided reason:
No choices exist for backend. please consider adding ATEN into
max_autotune_gemm_backends config
```

- first divergence：`lowering`；本轮未进入 runtime/correctness。
- `TORCH_COMPILE_DEBUG=1` 已生成 `fx_graph_readable.py` 与
  `fx_graph_transformed.py`，两者都是 `slice -> aten.mm`，证明 pad replacement 未发生。
- 编译在算法选择阶段终止，因此没有 `ir_pre_fusion.txt`、`ir_post_fusion.txt` 或
  `output_code.py`；不能伪造运行路径结论。
- 对照 NPU 配置：`aten.mm` 位于 `LOWERING_OVERRIDE_OP`，不在普通
  `lowering_fallback_list.py` 的 mm fallback 项；失败是上游测试限定候选为 TRITON 后没有选择，
  不是 eager 算子缺失。

本 case 显式使用 NPU device/backend，且已知通用 `transfer_to_npu` 会污染当前
`triton_experimental` backend loader 的 `get_gpu_type.cache_clear()`；因此继续使用更小的
`import torch_npu` 与显式设备注入，不加载该通用迁移层。

## 结论与归因

- GPU/reference 的 `dynamic-m-positive` 合同有效；当前 NPU 产品 baseline 明确在
  `config` 层关闭 pad-mm，因此 NPU 不命中是 `EXPECTED_DISABLED`，不能写成“未支持原因未知”。
- 原生直接入口的 `NO_TESTS` 是测试路由阻断。
- adapter 首轮的 `NoValidChoicesError` 是 GPU 测试把 GEMM 候选限定为 TRITON 与 NPU
  产品关闭 pad replacement 组合后的 lowering 阻断；加入 ATEN 候选后原始 mm 正确运行。
- 最终轮证明 `disabled-baseline-negative` 成立，并证明产品 gate 关闭时 dynamic-M 原图仍能
  correctness PASS；它不证明 NPU 已支持 pad-mm replacement，也不构成性能收益证据。

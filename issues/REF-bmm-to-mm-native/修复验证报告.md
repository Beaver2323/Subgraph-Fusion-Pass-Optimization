# REF-bmm-to-mm-native 修复验证报告

> 更新时间：2026-09-07 18:46 CST（UTC+08:00）
> 验证后端：`triton_experimental`
> 验证结论：PASS

## 问题描述

上游 batch=1 `bmm→mm` rewrite 在 NPU 上功能正确，但社区 shape 与三个敏感 shape 的 NPU Event p50
分别回退 12.46%、31.58%、18.79%、16.97%。原因是 torch_npu 将 NPU 纳入通用 GPU 判定后自动
继承了 CUDA 导向的盈利性决策。修复目标是在 experimental NPU backend 默认保留 bmm，同时保持门禁
可逆且不影响 CPU/CUDA。

## 修复内容摘要

- **修改文件**：experimental `config.py`、`fx_passes.py`、`overrides.py`，以及一个专门 UT。
- **修复方式**：产品代码修复；给已注册的上游 `bmm_to_mm` entry 安装 NPU-only live gate。
- **修复位置**：`torch_npu/_inductor/triton_experimental/`。
- **是否包含 C/C++ 变更**：否。

## 代码变更审查

- `config.py`：新增默认 `True` 的 `disable_bmm_to_mm`，注释绑定 T-079 数据。
- `fx_passes.py`：按 handler 名只定位目标 entry，保存原 predicate，判断输出设备后拒绝 NPU match。
- `overrides.py`：在 `triton_experimental` 激活时安装 gate。
- UT：覆盖 NPU-only、可逆、幂等。

```diff
+disable_bmm_to_mm: bool = True

+def _install_bmm_to_mm_gate():
+    ...
+    if ncfg.disable_bmm_to_mm and is_npu:
+        return False
+    return _original_check(match)

 def apply_npu_overrides():
     _disable_pad_mm_pass()
+    _install_bmm_to_mm_gate()
```

改动只改变 experimental NPU 的匹配资格，不替换 handler、不修改上游 PyTorch、不引入 fallback，也不
改变 mm/bmm lowering。

## 残余风险

- **未覆盖的近邻用例及原因**：未全量跑 joint-graph；门禁只包装单一 entry，CPU 透传和可逆路径已有
  专门测试。
- **未验证的边界场景**：未来硬件、未来 CANN 或新的 shape 子域可能令 mm 重新有利，应通过新一轮
  同后端数据后细化门禁。
- **NPU 能力覆盖度评估**：mm/bmm 两条能力均完整；本修复处置的是盈利性而非能力缺口。
- **需要后续关注的潜在问题**：把专门 UT 纳入 torch_npu CI，并在升级 PyTorch pattern 注册结构时
  检查目标 entry 仍可定位。

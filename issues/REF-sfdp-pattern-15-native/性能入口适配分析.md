## 原因：trace样例的零维Tensor不是生产调用允许的Python标量

```python
# torch/_inductor/fx_passes/fuse_attention.py:1235，注册输入节选
(_sfdp_pattern_15, _sfdp_replacement_15,
 [g(), g(), g(), m_2d(), c()], {}, _sfdp_extra_check(aten.div.Tensor))

# 同文件:1005，_sfdp_extra_check实际保留的guard
scale_factor = scale_factor_node.args[1]
if not isinstance(scale_factor, (float, int)):
    return False

# test/inductor/test_fused_attention.py:966起，原社区方法
scores = torch.matmul(q, k.transpose(-2, -1)) / 3.0
```

`c()`给模式追踪提供零维Tensor占位；当前派生执行器原样clone，成为运行时Tensor输入。
实际FX可见`div.Tensor(view_2, arg3_1)`，第二参数是FX节点，不是Python数值，guard应拒绝。
不能为获得ON而删除这个guard；也不能因直接运行search函数没有命中就推翻原例通过。

```text
派生search_fn(inv_scale=0维Tensor)
  → Dynamo div.Tensor(..., placeholder)
  → _sfdp_extra_check看见非float/int → False
  → 显式attention原图继续lowering → 数值通过
  → 执行器精确ON断言失败 → 阻止计时
```

下一步仅在运行边界修改派生输入：按参数名识别`inv_scale`，在compile之外将注册常量取成Python数值，
保持其值和所有Tensor shape/stride/dtype，分别记录标量合同。保留原guard，重新做OFF/ON、真实代码审查和数值门禁。
该修改不能套用到任意零维Tensor；其他合法的Tensor输入仍需保留Tensor语义。正在执行的公共worker不热修改。

# REF-b2b-gemm-native 最小适配报告

> 复核时间：2026-09-07 11:20 CST（UTC+08:00）｜T-077｜`AU-b2b-gemm`
> PyTorch：`8e86e0a23e3679c2bf3406cf0837fcb6297a5d9b`｜后端：`triton_experimental`
> 类型：六个社区 shape/pattern 的 NPU 镜像；`product_gate_bypassed=false`

## 1. 原生阻断

`test_b2b_gemm.py` 的 CUDA 测试类没有 NPU 入口，且上游 B2B handler 的 device guard 不接受 NPU。
adapter 必须同时覆盖四个正例以及 bad-pattern/bad-shape 两个负例，不能只运行可融合图。

## 2. 最小适配

```python
# issues/REF-b2b-gemm-native/npu_adapter.py:78-99
with torch._inductor.config.patch(b2b_gemm_pass=True):
    compiled = torch.compile(fn, options={"npu_backend": "triton_experimental"})
    self_target_count = counters["inductor"]["b2b_gemm"]
```

适配镜像六个冻结社区函数/shape/dtype 和正负 counter，只把输入改为 NPU；没有修改 device guard，
也没有强制添加一个无效 template choice。

## 3. 必要调用链

源码重建链：`adapter.main → six B2B variants → torch.compile → b2b_gemm pass
→ device guard rejects NPU → original GEMM path → correctness/counter assertions`。

## 4. 结果与边界

数值与负例均正确，正例因 guard 均为 target=0；正式 verdict 为
`EXPECTED_PRODUCT_DIVERGENCE`。capability probe 又证明当前没有有效 NPU B2B template，因此不绕过
guard 测性能；详见 [T-077 汇总](../../report/t077_npu_completion_20260902.md)。

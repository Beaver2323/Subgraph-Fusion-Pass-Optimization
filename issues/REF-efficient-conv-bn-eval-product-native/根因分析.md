> 更新时间：2026-09-14 21:11 CST（UTC+08:00）。裁剪根因已确认：HF32与折叠舍入交互；完整精度模式合同待复验。

## 已证实的事实

原社区 NPU 方法在首个 Conv1d 前向比较失败；原容差未变。
目标 handler 已实际改写，生成代码执行折叠权重和 NPU 卷积，非未命中、非 CPU fallback。
完整错误、参数及调用栈见[复现报告](复现报告.md)。尚无产品修复。

```python
# PyTorch/torch/_inductor/fx_passes/efficient_conv_bn_eval.py:24（核心公式摘录）
weight_coeff = torch.rsqrt(bn.running_var + bn.eps).reshape(target_shape)
coefff_on_the_fly = bn.weight.view_as(weight_coeff) * weight_coeff
weight_on_the_fly = conv.weight * coefff_on_the_fly
bias_on_the_fly = bn.bias + coefff_on_the_fly.flatten() * (conv.bias - bn.running_mean)
output = functional_call(conv, {"weight": weight_on_the_fly, "bias": bias_on_the_fly}, x)
```

实数域公式等价，但先缩放权重再卷积与先卷积再 BN 的舍入顺序不同。
社区 helper 的说明也明确存在数值稳定性的代价；不能仅凭数学等价保证原容差。

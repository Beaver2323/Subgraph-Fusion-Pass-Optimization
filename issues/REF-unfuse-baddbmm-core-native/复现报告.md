## 测试合同

上游方法：
`test/inductor/test_pattern_matcher.py::TestPatternMatcher.test_unfuse_broadcast_bias_baddbmm`；
冻结 PyTorch commit `8e86e0a23e3679c2bf3406cf0837fcb6297a5d9b`。

输入为 bias `[4,1,8]`、mat1 `[4,6,5]`、mat2 `[4,5,8]`，包含三个场景：

1. 无 pointwise consumer：保留 baddbmm；
2. broadcast bias + GELU：拆为 bmm + bias pointwise；
3. stride-0 expanded bias + ReLU：拆为 bmm + bias pointwise。

每个场景都有 compiled/eager 数值断言；结构断言要求负例含 baddbmm，正例不含
baddbmm 且含 bmm。GPU 紧凑 reference 中该 case 通过。

## 原生入口与两级适配

- 原生入口受 `HAS_GPU` 启动门阻断，退出 0 但 0 tests：`direct-aye30nne/`。
- device-only 适配真实进入测试，首个数值断言已完成，但 CUDA 专属 needle 失败：
  `adapter-rw6061en/`。

首次失败为：

```text
Expected to find "extern_kernels.baddbmm(" but did not find it
```

此时 transformed FX 仍是 `aten.baddbmm.default`；NPU output code 通过
`torch.ops.aten.baddbmm.default(...)` 调用 NPU 算子，而 CUDA 使用
`extern_kernels.baddbmm(...)`。二者都表示“未拆分”，因此是测试 codegen spelling
差异，不是产品行为错误。

最终适配仅在传给原 `FileCheck` 的字符串副本中执行：

```python
code.replace(
    "torch.ops.aten.baddbmm.default(", "extern_kernels.baddbmm("
).replace(
    "torch.ops.aten.bmm.default(", "extern_kernels.bmm("
)
```

原 output_code、FX、数值结果均原样保存；原方法、shape、broadcast/expand 和
check/check_not 顺序没有改变。没有用数值正确替代结构判定。

## 1. 原生阻断

社区事实源是 `test/inductor/test_scatter_optimization.py::TestScatterOpt` 的 8 个方法，端到端入口为
`test_cross_entropy_loss`。原模块只在 `HAS_GPU=true` 时由 `__main__` 调用 `run_tests()`；NPU 直接
运行返回码虽为 0，却执行 0 tests，因此不能记作 PASS。

```python
# test/inductor/test_scatter_optimization.py:189
def test_cross_entropy_loss(self):
    B, T, D, V = 32, 1024, 768, 50257
    ...
    def f(m, x, label):
        ce(m(x).view(-1, V), label.view(-1)).backward()
```

## 2. 最小适配

适配实现集中在 `runners/t080_npu_case.py`，不是产品 pattern 改写。它在导入社区模块后设置 NPU
设备，显式实例化原 `TestScatterOpt.test_*` 方法；原 shape、dtype、正负 guard、数值、梯度与目标
metric 均保持。测试入口是 `runners/run_t080_case.py`。候选能力阶段由它逐 case 执行；性能回退并
增加产品门禁后，兼容入口 `scripts/run_t080_scatter.sh` 已改为转入
`verify_t080_scatter_gate.sh`，避免绕过门禁重放候选 ON。

```python
# runners/t080_npu_case.py
upstream.GPU_TYPE = "npu"
upstream.HAS_GPU = True
torch.set_default_device("npu")
base_class = upstream.TestScatterOpt
result = unittest.TextTestRunner(...).run(
    unittest.TestSuite([NpuCase(method_name)])
)
```

唯一后端指标适配针对 `non-constant-base` 负例：CUDA scheduler 的 StarDep 过估算比 NPU 实际
`num_bytes_accessed` 多 8192 bytes。适配只接受该 case、该 actual/expected 组合；FX 必须仍保留
`aten.scatter.value`、target metric 必须为 0，因而没有放宽产品 guard。

## 4. 结果与边界

- 8/8 方法体执行：3D、非末维、负 dim、FP16/BF16、CrossEntropy 正例命中；short-index、dense、
  non-const 负例拒绝。
- CrossEntropy weight gradient 与 eager 参考一致；没有 CPU fallback。
- `product_gate_bypassed=false`。适配没有修改 selector/density/dtype guard。
- 完整社区 shape 暴露的两处 codegen 问题属于产品修复，不属于测试适配，见同目录《根因分析》与
  《修复验证报告》。
- pattern 原理、GPU/NPU 对照与性能解释见
  [`../../docs/T080_RESULT_AND_LEARNING_GUIDE.md`](../../docs/T080_RESULT_AND_LEARNING_GUIDE.md)。

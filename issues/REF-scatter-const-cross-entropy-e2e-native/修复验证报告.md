## 2. 修复代码框

编译参数修复把 Ascend option 从 AST constexpr 分层到 `NPUOptions`：

```python
# torch_npu/_inductor/triton_experimental/npu_triton_heuristics.py
cfg_kwargs = dict(cfg.kwargs)
auto_blockify_size = cfg_kwargs.pop("auto_blockify_size", None)
compile_meta["constants"].update(cfg_kwargs)
if auto_blockify_size is not None:
    options["auto_blockify_size"] = auto_blockify_size
```

物理 rank 晚于逻辑 rank 扩展时，零初始化改用可广播 typed scalar：

```python
# torch_npu/_inductor/triton_experimental/codegen/triton.py
ndim = V.kernel.triton_tensor_ndim()
if ndim == 0:
    return TritonOverrides.constant(value, dtype)
if value == 0:
    return TritonOverrides.constant(value, dtype)
```

两处改动没有修改 Scatter 的 shape/density/base/dtype guard。source overlay 在测试进程中确认实际加载
的是当前 torch_npu 工作树模块，而非旧 wheel。

## 3. 功能与完整 shape 验证

- 修复前：完整 OFF 编译依次复现上述两个异常；
- 修复后 smoke：完整 BF16 backward 编译、梯度正确性和 1×1 计时通过，生成代码含 8 个 Triton kernels，
  没有 CPU fallback；
- 峰值 allocated 约 13.72 GB，reserved 约 26.73 GB；
- 正式 OFF1/ON1/ON2/OFF2/OFF3/ON3 六个 fresh process 全部通过 correctness gate。

## 4. 性能结论与产品门禁

ON 相比 OFF 的 Event p50/p99 回退 10.50%/10.55%，host p50/p99 回退 10.57%/10.60%，峰值
allocated/reserved 增加 35.87%/5.51%，因此候选判定为 `PERF_REGRESSED`。产品不撤销通用 codegen
修复，而是在 backend-local 配置中默认关闭这一具体 rewrite：

```python
# torch_npu/_inductor/triton_experimental/config.py
disable_scatter_upon_const_tensor: bool = True

# torch_npu/_inductor/triton_experimental/fx_passes.py
if ncfg.disable_scatter_upon_const_tensor and is_npu:
    return False
return original_check(match)
```

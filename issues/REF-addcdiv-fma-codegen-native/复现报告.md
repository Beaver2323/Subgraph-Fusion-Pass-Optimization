## 初步判断

这是确定的 NPU 图模式能力缺口：同一个冻结 commit 的 GPU reference 命中并通过，NPU experimental
未重融合，首次分歧位于 `_is_addcdiv_fma_eligible` 的设备检查。并且后续还有两层待验证：
experimental fallback 注册是否保留 `aten.addcdiv` lowering，以及 NPU lowering 是否真正生成并支持
`tl.fma`/`div_rn`。

## 修复方向建议

- **根因初步分类**：NPU Inductor lowering/FX pass 覆盖缺失（图模式能力缺口）。
- **建议修复位置**：torch_npu `triton_experimental` 的 NPU 专用 post-grad 注册、
  `lowering.py` 与 `lowering_override_list.py`；不建议把私有 NPU 设备名硬编码回上游 PyTorch。
- **建议修复方式**：先用不改冻结源码的独立候选注册做功能探针；只有 counter、生成代码和
  数值全部通过后，才形成产品补丁和性能 OFF/ON。
- **预计是否需要重新编译 torch_npu**：若为纯 Python FX/lowering 注册，功能探针不需要；
  正式部署至少需要新进程加载修改，是否构建 wheel 由合入方式决定。

## 下游处理

传递给 diagnose 阶段；性能门禁保持关闭，不能把普通 div/mul/add pointwise 当作目标 ON。

## 问题描述

上游社区 `test_addcdiv_fma_uses_fma_and_div_rn` 要求 post-grad 将 FP32
`div → mul → add` 重融合为 `aten.addcdiv`，并生成 `tl.fma` 与
`triton.language.div_rn`。NPU 最小入口适配可完成编译和执行，但修复前融合计数为
0，FX 与生成代码仍是普通除、乘、加，社区 codegen 合同失败。

触发条件：冻结 PyTorch commit
`8e86e0a23e3679c2bf3406cf0837fcb6297a5d9b`，NPU 910B2，
`TORCHINDUCTOR_NPU_BACKEND=triton_experimental`，FP32 tensor 和字面量
`value=2.0`。

## 修复内容摘要

- **修改文件**：
  - `torch_npu/_inductor/triton_experimental/fx_passes.py`：增加幂等、NPU-only、
    FP32-only 的 addcdiv FMA post-grad pattern；
  - `torch_npu/_inductor/triton_experimental/lowering.py`：在统一 fallback 扫描后
    窄注册 `aten.addcdiv.default` 的 `div_rn + fma` lowering；
  - `torch_npu/_inductor/triton_experimental/overrides.py`：在 backend 激活时安装
    pattern。
- **修复方式**：补齐 experimental 编译器 pattern/lowering 注册覆盖。
- **修复位置**：仅 `torch_npu` 的 `triton_experimental` Python 路径。
- **是否包含 C/C++ 变更**：否。

## 代码变更审查

- **修改文件清单**：
  - `torch_npu/_inductor/triton_experimental/fx_passes.py`
  - `torch_npu/_inductor/triton_experimental/lowering.py`

- **关键 git diff 片段**：

  ```diff
  +def _install_addcdiv_fma_pass():
  +    # 仅 NPU + FP32 self/t1/t2/output + 非 Tensor scalar
  +    @register_graph_pattern(
  +        ...,
  +        pass_dict=post_grad.pass_patterns[2],
  +        extra_check=is_npu_addcdiv_fma_eligible,
  +    )
  +    def npu_fuse_addcdiv_to_fma(match, inp, t1, t2, value):
  +        counters["inductor"]["addcdiv_fma_fused"] += 1
  +        match.replace_by_example(repl, [inp, t1, t2, value])

  +@register_lowering(aten.addcdiv.default, broadcast=True)
  +def npu_addcdiv(self, tensor1, tensor2, *, value=1):
  +    quotient = ops.div_rn(t1_val, t2_val)
  +    ...
  +    return ops.fma(value_expr, quotient, self_val)

   _register_int64_fallbacks()
  +_register_npu_addcdiv_lowering()
  ```

- **改动合理性评估**：上游 guard 排除 NPU，experimental fallback 又覆盖上游
  lowering，两个缺口必须同时补齐。修复不改冻结 PyTorch，不把整个 op packet 加入
  通用白名单，只允许已动态证明的 NPU FP32 合同。FP16 首轮近邻失败后已收紧 guard，
  避免把 CUDA 的 dtype 范围机械迁移到 NPU。

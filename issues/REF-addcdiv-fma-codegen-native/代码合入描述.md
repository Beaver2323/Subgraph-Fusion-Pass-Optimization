# 【修改方案】

1. 在 `triton_experimental` 激活时，向 post-grad 第 2 轮注册 NPU 专用的
   `div → mul → add` 到 `aten.addcdiv` 重融合 pattern。
2. pattern guard 接受已在 910B2 动态验证的 FP32/BF16/FP16 `self/t1/t2/output` 和 NPU
   device。FP16 只接受具体 Python scalar；tensor-valued scalar 与非浮点 `self` 保持不命中。
3. experimental 的统一 fallback 扫描完成后，窄注册
   `aten.addcdiv.default` lowering。FP32/BF16 使用 `ops.div_rn` 和 `ops.fma`；FP16 在单 kernel
   内显式保留除法、乘法后的低精度舍入。
4. 为 `value=1` 在 decomposition 中被消去乘法后的 `add(div)` 结构增加 NPU 专属重融合 pattern。
5. 保持冻结 PyTorch 不变，不增加 CPU fallback，不跳过社区断言，也不把整个
   `addcdiv` packet 加入通用生成白名单。

# 【影响范围】

- 仅影响选择 `triton_experimental` 后端且满足 FP32/BF16/FP16 addcdiv pattern 的图。
- 不含 C/C++ 修改，无需重编译 torch_npu 二进制。
- FP16 进入后端专属精确路径；不使用 FMA/div_rn，避免改变 NPU eager 舍入语义。
- FP32/BF16 三轮性能均为 `PERF_NEUTRAL`。FP16 修复前 OFF 不正确，暂不声明 pass 收益。

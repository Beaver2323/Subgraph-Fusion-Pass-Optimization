# 修复 NPU triton_experimental 的 addcdiv 精度

本说明为当前本地实现的 PR 描述草稿，对应 [PR 46468](https://gitcode.com/Ascend/pytorch/merge_requests/46468)。9 月 20 日补充的 BF16 修复及专项测试尚未推送到产品 PR。

`torch.addcdiv(input, tensor1, tensor2, value=v)` 编译后会执行除法、乘法和加法。NPU 不同数据类型的舍入方式不同，直接套用同一种融合实现会让编译结果与直接运行结果不一致。

本修改在 `triton_experimental` 后端识别该计算，按输出类型生成代码。FP16 保留除法和乘法之后的 FP16 舍入；FP32/BF16 使用精确除法和融合乘加。BF16 的 Python 系数先转换为 BF16，再参与计算。例如 `value=0.1` 转换后为 `0.10009765625`，避免编译路径与直接运行使用不同系数。

`value=1` 时乘法会被消去，FP16 的除法后仍须保留舍入。该情况继续使用普通除法加法路径，并有单独测试。修改不涉及对外 API 或 C++ 代码。

验证环境为 NPU、CANN 9.2、triton_experimental。新增专项测试共 17 项，全部通过、无跳过，编译与直接运行的输出要求逐元素相等（允许误差为 0）：

- FP16/BF16/FP32 分别测试 `value=0.1、0.3、1.3、2.0、-0.75`，共 15 项。
- FP16 `value=1`，检查除法舍入和实际生成代码。
- FP16 非连续及广播输入。

测试文件为 `test/_inductor/test_triton_experimental_addcdiv_precision.py`。主要方法为 `test_scaled_addcdiv_matches_eager`、`test_fp16_value_one_preserves_div_rounding_without_refusion`、`test_fp16_strided_and_broadcast_inputs`。语法和差异空白检查通过。

测试基于 `cc0ded239cb1bad9981cf62f48adea79a5c79402` 加本地修复，使用独立的编译器 Python 文件和现有原生库，没有重建完整安装包。此前组合模型流水不包含本次 BF16 系数修复；本次未复跑完整模型或性能测试，远端 CI 未验证。

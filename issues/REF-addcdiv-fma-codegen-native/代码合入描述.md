# fix(triton_experimental): preserve NPU addcdiv low-precision rounding

## 【合入来源】

修复 `torch.addcdiv` 在 NPU 编译执行时与 eager 的低精度舍入不一致的问题。

## 【修改方案】

在 `triton_experimental` 中将符合条件的除法、乘法、加法重新识别为 addcdiv，并按数据类型生成计算代码：

- FP32/BF16 使用精确除法和融合乘加。BF16 的 Python 标量先转成 BF16，再参与计算，与 eager 保持一致。
- FP16 保留除法及乘法后的 FP16 舍入，避免融合计算改变结果。
- `value=1` 不强行改写为 addcdiv；FP16 的普通除法路径保留商的低精度舍入。

本次补测发现 BF16、`value=0.1` 时原实现有 374/4096 个元素不一致，最大绝对误差为 0.015625。原因是 eager 使用 BF16 舍入后的系数，而编译路径使用原 FP32 系数；本次已补上该转换。

已合并主线 `28a9bc52a5bf45a26b2700943cfaa13ceb8df2fc`，解决 `lowering.py` 冲突，同时保留主线的 softmax 处理逻辑。

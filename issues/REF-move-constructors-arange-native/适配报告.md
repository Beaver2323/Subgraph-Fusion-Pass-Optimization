# T-080 Constructor Mover NPU 最小适配报告

> 更新时间：2026-09-07 20:20 CST（UTC+08:00）
>
> 后端：仅 `triton_experimental`

## 1. 原生阻断

社区正例属于生成的 `GPUTests.test_move_arange_cuda`，负例属于 `TritonCodeGenTests`；NPU 上没有生成
这些 CUDA 类/后缀入口，因此原生模块未进入方法体。

```python
# torch/_inductor/fx_passes/post_grad.py:2488
def move_constructors_to_gpu(graph):
    ConstructorMoverPass(get_gpu_type(), ...)(graph)
```

## 2. 最小适配

正例直接调用原 `CommonTemplate.test_move_arange`，只把 `common` 和 `device` 绑定到 NPU；原社区
`generated_kernel_count=1` 判据不变。负例复用原函数、shape、mutation 与 compile，只把
`empty_strided_cuda(())` 字符串检查替换为 NPU 等价的 `empty_strided_npu(())`。

```python
# runners/t080_npu_case.py
def test_t080_move_arange_adapter(self):
    self.device = "npu"
    upstream.CommonTemplate.test_move_arange(self)

def test_t080_constructor_index_put_adapter(self):
    ...
    code = run_and_get_triton_code(f, x, mask)
    self.assertNotIn("empty_strided_npu(())", code)
```

## 3. 必要调用链

```text
run_t080_constructors.sh
  -> run_t080_case.py --adapter
  -> 原 CommonTemplate.test_move_arange / 等价 index_put 方法体
  -> torch.compile
  -> post_grad_passes
  -> move_constructors_to_gpu -> ConstructorMoverPass
  -> GraphLowering -> triton_experimental codegen
  -> kernel-count / NPU scalar-allocation / numerical assertion
```

性能 OFF 只把这一个 pass 调用替换为 no-op；ON 调用原函数，其他 post-grad passes 完全相同。

## 4. 结果与边界

- 2/2 方法体执行并通过；arange 正例一个 generated kernel，index_put 负例没有 NPU scalar allocation。
- 社区 length=32 的 3×OFF/3×ON Event p50 改善 0.46%，p99 回退 0.50%，为 `PERF_NEUTRAL`；峰值
  allocated/reserved 均不变。
- 1024、65536、1048576 只作为 tracker sensitivity，不冒充社区 benchmark。
- 无产品源码修复，`product_gate_bypassed=false`。完整原理与 GPU/NPU 对照见
  [`../../docs/T080_RESULT_AND_LEARNING_GUIDE.md`](../../docs/T080_RESULT_AND_LEARNING_GUIDE.md)。
